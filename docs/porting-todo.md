# 银行危机 Godot 移植 TODO

目标是在 Godot 中重现 `OriginGame.html` 的四层银行、后院、战斗、解谜、存档和逃生流程。建议先保持原作空间关系、玩法数值和低多边形恐怖风格，完成可通关版本后，再单独安排美术升级。

本清单基于 2026-10-02 的源码阅读；尚未完成原网页版的逐路线实玩核对。下列任务均为待办，现有试验场测试通过不代表银行移植完成。任务状态以 `project/tasks.json` 为准，验收项见 `project/acceptance.json`。

工具链和游戏目录已分层，详见 [项目分层说明](repository-layers.md)。当前 lab/probe 在 engine/sandbox/runtime；正式银行工程预留在 game/runtime，仍需按下列任务实现。

相机、AI、文本和关卡工具的候选方案见 [Godot 插件选型](godot-addons.md)。Phantom Camera 与 Debug Draw 3D 已有独立试验记录，正式银行接入及其他插件验证仍待实施，不构成移植任务的前置完成条件。

首版目标平台建议沿用当前 Windows 桌面环境。网页存档导入、Godot Web 导出、手柄、移动端、第五层可玩区域和高精度角色重制暂不纳入本轮功能等价范围；需要时另立任务。原作中不可进入的房间不自动扩展成新关卡。

这是开发顺序，不是强制玩家路线。UI、表现和音效从第一个切片就提供最低可用版本，最后阶段补齐与打磨；保存状态随每个系统同步扩展。建议先完成一楼切片与楼梯追踪原型，再据实际速度估算后续工期。

## 建议的工程结构

银行使用独立的 `game/runtime/project.godot`，通过 workspace.json 的 bank 项目配置运行。建议内容如下；目前仅预留目录，尚未创建正式工程：

```text
game/runtime/scenes/       正式入口、四层、后院、可复用门和机关
game/runtime/scripts/      玩家、战斗、敌人、交互、任务、保存与音频
game/runtime/data/         物品、难度、敌人、门锁、地图与事件定义
game/runtime/ui/           菜单、HUD、背包、地图、机关界面
game/runtime/assets/       正式运行资源；源文件在 game/source_assets，元数据在 game/catalog
game/runtime/testing/bank_adapter.gd
game/tests/            银行专属输入场景、负例和固定视角
```

稳定 ID 沿用原作，如 `g_inner`、`F3_sup`、`k_4fcard`，便于核对与保存。物理、导航和渲染用 Godot 实现；状态机、规则、数据表与事件顺序逐项映射。原作 `setTimeout` / `gameDelay` 应改为可冻结、可序列化的模拟事件队列。

现有测试桥继续只依赖 `GameAdapter`。正式银行需要增加 CLI 场景入口和支持选择 bank 的 QA 编排，不能让原 lab 测试冒充新关卡验收。接口确需扩展时，同时验证 lab、probe 和 bank；新的按键、右键、滚轮或 UI 输入只能通过有界协议进入正常输入处理器。

现有资产装配器只支持矩形单层，不能直接承担四层银行。复用其导入、审计、预览和版本管理，关卡布局与连续楼梯使用正式场景或专项构建脚本。
