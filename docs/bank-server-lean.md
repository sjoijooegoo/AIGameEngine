# 银行合作模式：减少专用服务端计算

当前源码为 `bank-combat-v7`、协议 `5`。公网仍运行用户此前指定的 v6，现有客户端包也仍是 v6；本次没有替换公网服务、WSL 或发布包。v7 必须配套导出两端，旧客户端会被版本检查拒绝。

## 计算分工

| 内容 | 服务端 | 客户端 |
| --- | --- | --- |
| 活体丧尸 | AI、导航、位置、血量、攻击/抓取和命中体 | 插值和完整人物表现 |
| 普通尸体 | 一个躯干球体的墙/地面扫掠，以及简化枪击命中体 | 完整骨骼、关节约束、落地和局部受力 |
| 尸体撞击活体 | 服务端扫掠判定、一次性击退 | 表现结果；本地尸体不能修改活体 |
| 尸体休眠 | 停止更新，不再绑定玩家上下文或推进动画/时钟 | 停止本地求解；收到受力事件后唤醒 |
| 活体动画 | 保留影响头、身体、四肢命中和攻击接触的骨骼链 | 完整原生动画和骨骼混合 |

服务端的尸体分支不再运行八轮关节约束、额外接触修正、逐关节碰撞和骨骼姿态投射。每个运动中的尸体只对躯干做原有墙/地面扫掠；霰弹枪抛飞尸体撞退活体的行为继续由权威端判定。单人模式保留原来的完整求解。

活体动画仍用原生采样、脚部接地、命中反馈和攻击接触时序。服务端只缩小过渡混合/基础姿态保存的骨骼范围，保留所有命中骨骼的祖先链，并跳过阴影图层更新。没有通过降低 tick 或删除活体命中动画节省计算。

## 网络状态

敌人快照第 9 项从持续变化的关节数组改为不可变的尸体事件状态：死亡种子、递增版本、最多六次受力事件，以及休眠时的一次简化落点。死亡种子保留当时的初始关节和速度，用于客户端启动物理；之后不再发送当前关节姿态。

事件包含在已有的基线/增量恢复机制中。丢失单个增量后，后续状态仍能恢复死亡和近期受力；重复包不会重复施力。基线刷新和晚加入可以重发死亡种子，因此不是“死亡数据绝不重传”。长时间断线时可能略过更早的纯表现受力，血量和死亡结果不受影响。

客户端固定以 60 Hz 推进本地关节物理，单帧最多追赶八步。晚加入者从简化休眠落点初始化一次，然后在本地落稳；已经在场的客户端不会被服务器落点或后续根节点快照拉回。重开局会清空事件消费状态。

## 取舍和边界

不同玩家看到的尸体四肢、最终姿态和落点允许有差异。尸体枪击遮挡和撞退活体以服务端的简化代理为准，不保证和某个客户端的每根四肢完全重合。客户端承担更多尸体计算；目前沿用完整求解器和休眠，没有新增距离裁剪或尸体数量上限。

网络传输仍使用现有 ENet/TCP 兼容通道，权威模拟保持 60 Hz。该改动减少尸体物理和表现计算，不会消除活体 AI、寻路、拥挤碰撞、VPS CPU steal 或公网线路停顿。

## 验证

本次只选择当前银行的本地契约、骨骼计算对比和双人真实输入连续帧；不运行历史试验场，也不重新跑公网压力/驻留测试。证据和具体结果见 `project/evidence/bank-server-lean-20261019/report.json`。

此前 VPS 尸体求解平均约 4–5 ms/帧，这只是选择优化对象的旧测量。本次还没有同条件 VPS 前后性能对照，不能把移除的代码量直接换算成 CPU 降幅或承载人数，也没有新的 2 核 4 GB 容量保证。
